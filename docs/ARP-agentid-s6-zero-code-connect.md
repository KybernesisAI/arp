# AgentID — Slice S6: zero-code connect (owner onboarding)

**Parent:** `docs/ARP-agentid-plan.md` §6 (S6 was "ecosystem tiers + commerce"; onboarding is pulled forward as **S6a** because the S4 live gate showed the customer path is unusable for non-technical owners — Ian, 2026-09-18: "3,4,5 are insanely complicated… UX for non-techy people is a must"). Commerce/tiers move to **S6b**.
**Branch:** `agentid-s6-connect` (ARP) + `identity-connect` (`~/platform`). Commits tagged `[agentid/s6]`.
**Goal:** an owner connects their agent to their `.agent` name with **one action on one screen**: paste the agent's URL, click Connect, see "Connected". No package install, no code edit, no environment variables, no redeploy, no second step. The developer path (`eve add @kybernesis/identity` + `arpAuth()`) remains the *integration* path for platforms, and Kybernesis agents ship with it pre-wired.

---

## 0. Ground truth (do not re-research)

- Today's attach (`POST /api/agents/[did]/runtime`, S4 P6) is a two-round-trip challenge dance: first call returns `AGENTID_CHALLENGE`; the owner sets `ARP_AGENT_DID` + `AGENTID_CHALLENGE`, redeploys, calls again, gets `ARP_AGENT_CREDENTIAL` (shown once), sets it, redeploys. Verified live on exe.dev with Kyber + Sid; it took a developer with ssh.
- The runtime needs exactly three facts: its DID, the issuer, and a long-lived agent credential (for outbound `ask_*_agent` calls). Inbound auth needs no secret (ES256 push tokens verified via `gateway.arp.run/.well-known/jwks.json`).
- The gateway already holds an ES256 signer (`ARP_CLOUD_PUSH_SIGNING_JWK`) and publishes its JWKS. The console (Vercel) holds no signing key. Console and gateway share the Neon database.
- `@kybernesis/identity@0.1.1`: `identityChannel()` serves `GET /eve/v1/arp/.well-known/agentid-verification` + `/health` from env; `arpAuth()` reads `ARP_ISSUER` / `ARP_AGENT_DID`; `arpPeers()` reads `ARP_AGENT_CREDENTIAL`. Eve routes: `POST(path, (req, args) => Response)`. Self-hosted eve agents have a writable app dir (`.eve/`); Vercel-hosted ones do not.
- Kybernesis agents are scaffolded by `@kybernesis/create` (`packages/create/src/init.ts` writes `agent/**`), run on exe.dev via `@kybernesis/exe` + systemd, and are managed by `@kybernesis/manage` (KYBER Studio can install packages + restart).

## 1. Decisions

| # | Decision | Why |
|---|---|---|
| S6-1 | **Connect is one console action.** `POST /api/agents/[did]/connect { url }` does everything: creates the runtime link + challenge, mints a single-use connect ticket, hands the ticket to the gateway, which signs a **connect token** and pushes it to the runtime; the runtime redeems it, stores its config, and the gateway verifies the identity document in the same round trip. Result: `connected` / `not_reachable` / `not_arp_ready` / `bound_elsewhere`. | One click, one round trip, no owner-side secrets. |
| S6-2 | **The runtime configures itself** from the connect token: `POST /eve/v1/arp/connect { token }` → verify ES256 against `<iss>/.well-known/jwks.json` (iss allow-list: `ARP_ISSUER` or `https://gateway.arp.run`), `aud` = this runtime's URL, `kind: 'arp-connect'`, 5-minute TTL, single use → redeem at `POST <iss>/agent-api/bootstrap` (bearer = the token) → receive `{ did, issuer, credential, challenge }` → persist. **Config resolution order:** explicit options → env (`ARP_*`, `AGENTID_CHALLENGE`) → the identity store. Store default: file `<app>/.eve/arp-identity.json` (0600), path override `ARP_IDENTITY_FILE`. Hosts without a writable disk keep the env path (the console shows the one-block fallback only when the runtime reports `store: 'none'`). | No env vars, no redeploy; the secret is generated by ARP Cloud and delivered over the token exchange, never typed by a person. |
| S6-3 | **Hijack protection = first bind wins, rebind only from the same tenant.** The gateway refuses to connect a URL whose origin is already bound (`agents.push_url`) to an agent in another tenant; a runtime that is already configured accepts a new connect token only from the same issuer (rotation/re-bind by the owner). Disconnect in the console clears the binding on both sides. | Anyone can *reach* an agent URL; only its owner can bind it first. Same trust model as webhook registration. |
| S6-4 | **The gateway owns the token exchange** (`POST /internal/connect` for the console, `POST /agent-api/bootstrap` for runtimes) because it holds the signer. Console → gateway auth is the ticket row itself: an unguessable single-use `agent_connect_tickets.id` that only the console can create (shared DB). No new shared secret. | Zero new env on Vercel (hidden vars cannot be managed from a dev box anyway). |
| S6-5 | **Kybernesis agents ship pre-wired.** `@kybernesis/create` scaffolds `agent/channels/arp.ts`, `agent/tools/arp-peers.ts`, `agent/instructions/arp.md` and puts `arpAuth()` in the eve channel; `kyb doctor` flags a missing `arpAuth()`. Registry item unchanged for non-Kybernesis eve agents. | The owner of a Kybernesis agent never installs anything. |
| S6-6 | **Console copy is owner-grade.** "Connect your agent" / "Connected to https://…" / "Disconnect". Names, not DIDs: the pair page accepts `sid` or `sid.agent` and resolves it. The advanced (env-var) path lives under a collapsed "Set up by hand" for other frameworks. | The buyer is an owner, not a developer. |

## 3. Acceptance gate

1. Full workspace gate green (ARP) + identity/create tests green (platform).
2. From a clean `.env.local` (no `ARP_*`), an owner connects `kyber.exe.xyz` to `kyber.agent` and `sid-agent.exe.xyz` to `sid.agent` from the console in **one click each**; no ssh, no redeploy.
3. A connect against a URL already bound to another tenant's agent is refused with `bound_elsewhere`; a replayed connect token is refused.
4. `ask_sid_agent` round trip and a policy denial still work after the switch (audit chain shows both).
5. `npx @kybernesis/create` scaffolds an agent that is ARP-ready with no extra steps.

## 4. Conservative calls

- Vercel-hosted eve agents (no writable disk) keep the env-var path; the console detects `store:'none'` and shows the one-block fallback. A hosted secret store (ARP Cloud keeps the credential and the runtime fetches it with a device key) is S6b.
- "Pick from KYBER Studio / exe.dev" (no URL at all) is S6b: needs the control plane to list the owner's agents.
- The connect token binds to the URL **origin**; path-scoped multi-agent hosts (`/agents/<x>/eve/v1/arp`) are supported for binding but the origin-collision check is per origin (documented).
- The old two-step attach route stays for the manual path; it is no longer linked from the primary UI.
